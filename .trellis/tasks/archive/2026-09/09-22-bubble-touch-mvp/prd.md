# Bubble Touch MVP

## Goal

验证 Bubble Touch 核心物理引擎 —— 通过一个可在浏览器直接打开的 H5 demo，让用户能亲手按压一块起泡胶并感受到 3-5 秒的慢回弹手感，确认"是不是真的像实体起泡胶"。

交付物：本地双击 `index.html` 就能玩的单页 demo。

## Background

`E:\slogan\Bubble-Touch-产品方案.md` 已给出完整产品文档（15 章、迭代路线、商业化设计）。当前任务只覆盖 Phase 1（MVP）中的核心验证环节：**慢回弹手感**。

## Confirmed Facts

- 框架选型：**uni-app**（用户确认）
- 目标平台：**H5**（浏览器优先；用户暂未注册微信小程序账号，开发者工具不可用）
- 项目目录：`E:\slogan\`（目前完全为空，无 `package.json`、`src/`、脚手架）
- 物理引擎规格（来自产品方案 §五）：
  - 网格 30×30，慢回弹 3-5 秒，弹性系数 0.3-0.5，阻尼 0.05-0.15，塑性 0.2-0.4
- ASMR 音效、UI 主题切换、用户统计 —— **MVP 阶段不做**
- 微信小程序开发者账号 —— **用户未注册**，MVP 阶段不交付小程序

## Requirements (MVP 范围)

1. **核心交互：单指按压起泡胶**
   - 触摸/鼠标按下：起泡胶在手指位置凹陷
   - 持续按住：凹陷持续，按压力度影响凹陷深度
   - 松开：凹陷以 3-5 秒慢回弹恢复
2. **视觉：一整块半透明起泡胶**
   - 充满屏幕约 80%
   - 多层半透明色叠加 + 内部气泡 + 表面高光
   - 边缘柔软过渡（径向渐变）
3. **3 种颜色主题**
   - 樱花粉 `#FFB6C1`
   - 雾霭蓝 `#B0E0E6`
   - 薰衣草 `#E6E6FA`
   - 提供切换按钮
4. **性能**
   - H5 端主流浏览器（Chrome / Safari / Edge 最新两个大版本）60fps
   - 单文件可运行（不依赖后端）

## Acceptance Criteria

- [ ] 在 HBuilderX 中"运行 → 运行到浏览器 → Chrome"启动后，5 秒内进入可交互状态
- [ ] 按压起泡胶时，凹陷响应延迟 < 50ms
- [ ] 松开手指后，起泡胶完全恢复原状时间在 3-5 秒区间
- [ ] 切换 3 个主题颜色，画面正确刷新
- [ ] 控制台无报错（无 404、无 JS 异常）
- [ ] Chrome DevTools Performance 录制 10 秒按压+松开循环，FPS ≥ 50
- [ ] 交付物为标准 uni-app 项目结构（`src/pages/index/index.vue` + `pages.json` + `manifest.json`），可在 HBuilderX 中打开并编译到 H5

## Out of Scope (MVP 不做)

- ASMR 音效系统
- 揉捏、拉伸、拍打交互（只做按压）
- 内部气泡浮动动画（静态气泡即可）
- 用户数据统计（今日按压次数等）
- 微信小程序编译产物
- 多主题扩展（双色混合、彩虹）
- 商业化相关功能

## Technical Notes

- **uni-app 项目结构（已确认）**：从 MVP 阶段就用 uni-app 标准结构，不走"先原生 HTML 再迁移"路线。好处是后续 Phase 2 加页面、分包、迁移到微信小程序无需重构项目结构。
- **目标平台优先级**：H5（用户当前可立即跑通） > 微信小程序（账号未注册，暂不能跑但代码需兼容）
- uni-app 编译配置需在 `manifest.json` 中将 H5 设为第一目标平台
- 物理引擎算法（来自方案 §五.2）：弹簧-阻尼-塑性模型，每个网格点维护 `displacement / velocity / plasticDeform`，逐帧 `updatePhysics(deltaTime)` 推进状态
- uni-app Canvas 2D 通过 `<canvas>` 组件 + `canvas-id` 引用；触摸事件用 `@touchstart/@touchmove/@touchend`
- 跨平台兼容要点：H5 端用 mouse/touch 事件双支持；小程序端只处理 touch

## Decisions Log

- 2026-09-22 Q1 决策：**MVP 直接走 uni-app**（用户选 B）。不走"原生 HTML → uni-app 迁移"路径。代价：MVP 阶段 2-3 天需在脚手架 + 构建工具上，但项目结构一步到位。
- 2026-09-22 Q3 决策：**凹陷算法用方案原版（弹簧-阻尼-塑性），20×20 网格起步**（用户选 A）。理由：真实感最高，H5 主流浏览器可稳跑 60fps；手感到位后再升 30×30。
- 2026-09-22 Q2 决策：**物理参数用方案中间值**（用户选 A）。弹性 0.4、阻尼 0.1、塑性 0.3。理由：调参空间最大、与方案文档对齐，便于后续记录调整。
- 2026-09-22 Q4 决策：**首次按压默认最大形变 60%**（沿用方案 §五.1 的 `最大形变: 60%`，未单独询问用户，归入 Q2 决策一起记录）。理由：方案给的范围中点，足够大以体现"果冻感"，不至于压穿底部。
- 2026-09-22 Q5 默认决策：**支持鼠标 + 触摸双输入**（用户未反对，按 H5 端最佳实践默认开启）。
- 2026-09-22 Q6 默认决策：**3 种纯色主题 + 切换按钮**（沿用方案 §四）。MVP 不做双色/彩虹扩展。
- 2026-09-22 Q7 实现期发现：**物理算法调整为临界阻尼 + 塑性 drain**（非原方案 §五.2 的纯弹簧-阻尼-塑性）。原因：直接用低阻尼系数（0.1）会导致按压时振荡；改为内层弹簧用临界阻尼（k=80, c≈2√k）让单点快速收敛到目标位置，外层用 `drainRate` 慢慢释放塑性偏移，3-5 秒"慢回弹"感来自 drain 而非弹性。原方案描述仍适用于"概念模型"，但具体参数含义已变。
